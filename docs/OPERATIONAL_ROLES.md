## 2. 各担当の標準業務手順 (SOP)

### 2.1. 手当関係の集計担当
手当集計担当者は、システムが自動計算した「祝日手当（休日給）」の時間数が、実際の勤務動態と合致しているかを検証し、ロックする役割を担います。

#### 【定常手順（毎月25日〜月末）】
1. **検証画面へのアクセス**
   - 消防ポータルシステム管理画面から「**祝日手当検証**」メニューを開きます。
2. **自動計算結果の確認**
   - 対象月度（例: `2026-05`）を選択し、各職員の「祝日当直回数」「祝日非番回数」「スライド（振替）日数」および「合計手当時間数」を確認します。
3. **詳細の突合と手動調整**
   - 異常値（例: 休んでいるのに手当がカットされていない、など）がある場合、職員名をクリックして「個別詳細」を表示します。
   - 必要に応じて、実際の勤務実態（スライド元の祝日など）と照らし合わせ、画面上で時間数を手動で調整（ドラフト保存）します。
4. **データの確定（ロック）**
   - 検証が完了したら、「**確定（ロック）**」ボタンを押します。
   - 確定されたデータはロックされ、その後に勤務表（シフト）が書き換わっても手当時間は自動更新されなくなります（再計算による混乱を防ぐため）。

### 2.2. 法律関係確認担当
法律関係確認担当者は、手当計算の根拠となる「国民の祝日法」や「地方自治体の消防職員給与条例（年末年始の範囲や休日給の支給割合など）」に変更がないかを監視し、プログラムに反映する役割を担います。

#### 【法改正・条例改正時の手順】
1. **祝日判定ユーティリティの更新**
   - 新しい祝日の新設や、年末年始期間の定義変更があった場合、[server/utils/holidays.js](file:///home/vehikel57oval/勤務表/server/utils/holidays.js) の判定ロジック（`getJapaneseHolidayWithoutSub` や `getHolidayType`）を修正します。
2. **テストスクリプトの追加・更新**
   - [server/db/test_allowance.js](file:///home/vehikel57oval/勤務表/server/db/test_allowance.js) に、改正後のカレンダーパターンを想定したテストケース（期待される手当時間数など）を追記します。
3. **検証テストの実行**
   - ターミナルで以下のコマンドを実行し、すべてのテストが正常にパスすることを確認します。
     ```bash
     node server/db/test_allowance.js
     ```
   - テストが失敗した場合は、手当の自動計算ロジック（[server/routes/admin.js](file:///home/vehikel57oval/勤務表/server/routes/admin.js) 内 `calculateHolidayAllowanceInternal`）との整合性を確認・デバッグします。

### 2.3. システム説明書作成担当
システム説明書作成担当者は、システムの使い方や内部仕様がブラックボックス化するのを防ぐため、ドキュメントを常に最新の状態に保つ役割を担います。

#### 【システム改修時の手順】
1. **仕様ドキュメントの更新**
   - システム全体の共通ルール（勤務サイクル、休暇消化の計算、画面構成）に変更があった場合、[docs/BUSINESS_RULES.md](file:///home/vehikel57oval/勤務表/docs/BUSINESS_RULES.md) を速やかに更新します。
   - 祝日手当の計算方法に変更があった場合は、[docs/HOLIDAY_ALLOWANCE_RULES.md](file:///home/vehikel57oval/勤務表/docs/HOLIDAY_ALLOWANCE_RULES.md) に改訂履歴と新ルールを明記します。
2. **操作説明書の改訂**
   - 一般職員や管理者が操作する画面の変更（ボタンの追加や名称変更など）があった場合、ポータル内のヘルプページやPDFマニュアルの該当部分を改訂します。

## 3. GitHubを介した共同作業と共有方法

作成したドキュメントやプログラムの変更内容を、他の担当者や本部に共有する手順です。

1. **変更ファイルの確認**
   ```bash
   git status
   ```
2. **コミット（変更の記録）**
   ```bash
   git add docs/OPERATIONAL_ROLES.md
   git commit -m "docs: 運用の役割分担と業務手順書を新規作成"
   ```
3. **プッシュ（GitHubへの送信）**
   ```bash
   git push origin main
   ```
   *これにより、GitHub上の他のメンバーもブラウザからこの手順書（マークダウン）を確認できるようになります。*
